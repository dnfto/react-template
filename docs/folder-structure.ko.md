# 폴더 책임 설명

## 루트

- `.github/workflows`: PR과 main push에서 실행되는 CI 파이프라인입니다.
- `.husky`: 커밋 전 자동 품질 검사를 실행합니다.
- `.vscode`: 팀 공통 에디터 경험을 맞춥니다.
- `public`: 빌드 과정 없이 그대로 배포되는 정적 자산을 둡니다.
- `src`: 애플리케이션 소스 코드입니다.
- `tests`: 앱 코드와 분리된 테스트 인프라와 시나리오입니다.

## src/app

애플리케이션 시작점, 전역 Provider, 라우터, 레이아웃을 둡니다. 특정 feature의 업무 로직은 이곳에 두지 않습니다.

## src/shared

여러 feature가 재사용하는 안정적인 공통 계층입니다. API 인프라, UI 프리미티브, 환경 설정, 순수 유틸리티, 공통 타입을 둡니다.

## src/features

제품 기능을 도메인 단위로 담습니다. 기능이 커지면 내부에 `api`, `model`, `queries`, `components`, `lib` 등을 만들 수 있습니다.

## src/widgets

페이지에서 재사용하는 큰 UI 블록입니다. 여러 feature를 조합할 수 있지만, 앱 전체 설정이나 라우팅 책임은 갖지 않습니다.

## src/pages

라우트에 매핑되는 화면입니다. 페이지는 feature와 widget을 조합하고, 라우팅 관점의 화면 구성을 담당합니다.

## tests

테스트 종류별로 분리합니다. 컴포넌트, 훅, API, 통합, E2E 테스트의 실행 목적이 다르기 때문에 한 폴더에 섞지 않습니다.
