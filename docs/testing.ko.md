# 테스트 전략

## Component Test

UI 프리미티브나 작은 컴포넌트가 접근 가능한 DOM을 렌더링하는지 확인합니다. 구현 세부사항보다 사용자에게 보이는 역할과 텍스트를 기준으로 검증하세요.

## Hook Test

상태 전환이나 재사용 로직을 컴포넌트 렌더링과 분리해 검증합니다. 훅이 외부 API에 의존한다면 MSW나 provider wrapper를 사용하세요.

## API Mock

MSW는 네트워크 경계를 실제처럼 유지하면서 테스트를 안정적으로 만듭니다. API 함수 자체를 mock하기보다 HTTP 응답을 mock하면 통합 흐름을 더 잘 검증할 수 있습니다.

## Integration Test

페이지가 Query, API mock, UI 컴포넌트를 함께 사용해 기대한 화면을 만드는지 확인합니다. 라우팅과 상태 관리가 엮이는 영역은 통합 테스트가 특히 유용합니다.

## E2E Test

Playwright는 브라우저에서 실제 사용자 흐름을 검증합니다. 모든 케이스를 E2E로 만들면 느려지므로, 핵심 업무 흐름과 회귀 위험이 큰 경로에 집중하세요.
